Flag / entradaUso

--scanners vulnSó vulnerabilidades (o padrão inclui segredos)
--severityFiltra o que aparece e o que vale para o código de saída

--audit-level=high (npm)Só o código de saída; não filtra o relatório
--omit=dev (npm)Audita só o que vai para produção

Tag × SHA

git ls-remote --tags https://github.com/DONO/REPO 'vX.Y.Z*'
# uma linha        -> tag leve: o SHA já é o commit
# duas linhas      -> tag anotada: use a linha terminada em ^{}
git ls-remote --tags https://github.com/DONO/REPO | grep SHA   # descobrir a versão exata

No workflow: uses: DONO/REPO@<sha-de-40-caracteres> # vX.Y.Z. Para github/codeql-action/upload-sarif, o repositório é github/codeql-action.

Cooldown do uv

[tool.uv]
exclude-newer = "7 days"                  # aceita "24 hours", "1 week", ISO 8601 (P7D)
exclude-newer-package = { certifi = false }   # isenta um pacote
  • Exige uv recente: o uv:0.5 do Dockerfile falha ao ler (failed to parse year in date "7 days").
  • Pode rebaixar uma correção de segurança recém-publicada (testado com o certifi).
  • Mínimo do pyproject.toml mais novo que o corte: o uv lock falha (unsatisfiable), não rebaixa.
  • O uv.lock ganha um bloco [options] com exclude-newer-span = "P7D". Guarda o prazo, não a data: o uv lock --check e o uv sync --locked não quebram com o passar dos dias (testado com o relógio +5 dias).
# sem uv instalado (Windows): o mesmo uv do Dockerfile
docker run --rm -v "${PWD}:/w" -w /w python:3.12-slim sh -c "pip install -q uv==0.13.1 && uv lock"
# o que o cooldown seguraria
... uv lock --upgrade --dry-run

dependabot.yml

CampoValor / efeito
versionsempre 2
package-ecosystemuv · npm · docker · github-actions
directory / directoriesOnde está o manifesto; só directories aceita glob
schedule.intervaldaily, weekly, monthly, quarterly, semiannually, yearly, cron
cooldownSó atualizações de versão; padrão de 3 dias
groupsJunta atualizações num PR só
open-pull-requests-limitPadrão 5 abertos; segurança tem limite próprio de 10

Limite: o Dependabot não gera alertas para actions fixadas por SHA.

Se o portão de SCA ficar vermelho sem commit novo

  1. Atualize a biblioteca (uv lock --upgrade-package / npm update).
  2. Sem versão corrigida: o ignore-unfixed já cobre.
  3. Falso positivo: suprimir aquele aviso, com justificativa (.trivyignore).
  4. Desligar o portão não está na lista.
