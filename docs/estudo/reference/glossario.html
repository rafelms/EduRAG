Referência · termos usados nas aulas

Glossário

As aulas usam estes termos sempre com este sentido.

Bypass list
Quem pode ignorar as regras de um ruleset. No protege-main, fica vazia. Aula 0001
Advisory (aviso de segurança)
O registro público de uma vulnerabilidade, com versões afetadas e corrigidas. Identificado por GHSA-… (banco do GitHub) ou CVE-… (catálogo público). Aula 0004
Check obrigatório (required status check)
Um job da CI que precisa ficar verde para o merge ser liberado. É identificado pelo id do job no workflow. Aula 0001
Cadeia de suprimentos (supply chain)
Tudo o que o seu código usa e não foi você que escreveu: bibliotecas, imagens base e actions. Um ataque a qualquer elo chega até você. Aula 0003 (detalhe na etapa 6)
Conjunto de regras do Semgrep
Um pacote de regras do registro do Semgrep, como p/default. O Semgrep o chama de ruleset, mas nesta trilha ruleset é só o do GitHub. Aula 0003
Cooldown
Uma espera mínima, em dias, antes de aceitar uma versão recém-publicada. No uv é o exclude-newer; no Dependabot, a opção cooldown, que só vale para atualizações de versão. Aula 0005
DAST
Dynamic Application Security Testing: testa a aplicação rodando, de fora, como um atacante faria. Aula 0003
Entropia
O quanto um texto parece aleatório. O gitleaks a usa para separar chaves reais de textos comuns que casam com a mesma expressão regular. Aula 0002
Falso positivo
Um achado de ferramenta de segurança que não é problema de verdade. Só deve ser suprimido com uma justificativa escrita. Aula 0002
Fingerprint
A identificação única de um achado do gitleaks (commit:arquivo:regra:linha). É o que vai no .gitleaksignore. Aula 0002
Menor privilégio
Dar a cada peça só as permissões de que ela precisa. Num workflow, é o bloco permissions. Aula 0002
Modo estrito
A regra "Require branches to be up to date": a branch do PR precisa estar atualizada com a main antes do merge. Aula 0001
Portão (gate)
Uma verificação que bloqueia, e não só avisa. Uma ferramenta vira portão quando o job dela entra nos checks obrigatórios. Aulas 0001, 0002
Revogar
Invalidar uma chave no serviço que a emitiu. É o primeiro passo diante de um segredo vazado. Aula 0002
Ruleset
Uma lista nomeada de regras que o GitHub aplica a branches escolhidas. Vários rulesets se somam. Aula 0001
SARIF
Formato JSON padronizado para resultados de análise estática. É o que a aba Security → Code scanning do GitHub recebe. Aula 0003
SAST
Static Application Security Testing: analisa o código-fonte sem executá-lo, em busca de padrões perigosos conhecidos. Aula 0003
SCA
Software Composition Analysis: compara as bibliotecas dos seus lockfiles com um banco de vulnerabilidades conhecidas. O resultado muda com o tempo, mesmo sem commit novo. Aula 0004
SHA (de commit)
O identificador de 40 caracteres de um commit. Numa action, @<sha> é imutável; já uma tag pode ser movida. Em tag anotada, vale o SHA da linha com ^{}. Aulas 0004, 0005
Segredo
Qualquer valor que dá acesso a algo: senha, chave de API, token, chave privada. Aula 0002
Severidade
O peso que uma regra dá ao achado (no Semgrep: INFO, WARNING, ERROR). Um portão pode barrar só a partir de uma severidade. Aula 0003
SQL injection
Quando um valor vindo de fora é colado no texto da consulta e passa a ser interpretado como SQL. A defesa é passar o valor como parâmetro, separado do comando (CWE-89). Aula 0003
Varredura de histórico
Uma análise de todos os commits do repositório, e não só dos novos. Feita uma vez, descobre se algo já vazou. Aula 0002
