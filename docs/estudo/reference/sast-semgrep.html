Rodar local

uvx semgrep@1.180.0 scan --config p/default --metrics off
echo $?   # sem --error: 0 mesmo com achados
FlagUso
scanModo sem conta (o semgrep ci exige SEMGREP_APP_TOKEN)
--config p/defaultConjunto de regras do registro; baixado a cada execução
--metrics offNão envia métricas ao baixar regras
--sarif-output=arq.sarifGrava uma cópia em SARIF
--severity ERRORSó regras dessa severidade (INFO, WARNING, ERROR)
--errorSai com 1 se houver achado (vira portão)
--exclude PADRÃOPula arquivos ou pastas

Códigos de saída: 0 ok · 1 achados (só com --error) · 2 erro fatal · 7 configuração ausente.

Regras de SQL (SQLAlchemy) testadas

CódigoRegra no p/default
session.execute("..." + x)sqlalchemy-execute-raw-query (o p/python não pega)
session.execute(text(sql_concatenado))avoid-sqlalchemy-text
text("SELECT 1")nada (string fixa)
text("... = :nome") + {"nome": x}nada: é a forma segura

Falso positivo

  • Na linha: # nosemgrep: <id-da-regra> na linha do achado ou na anterior, sempre com o id e com o motivo num comentário ao lado.
  • Arquivo inteiro: .semgrepignore (sintaxe de .gitignore). Use pouco.

Quando algo dá errado

SintomaCausa provável
Envio falha com erro de permissãoFalta security-events: write
Portão vermelho e aba Security sem dadosPortão antes do envio na ordem dos steps
Job vermelho "do nada", sem mudar códigoRegra nova no p/default (as regras não são fixadas pela versão)
Saída 7Faltou --config
Prova passou verdeUsou p/python com execute("..." + x), o arquivo não está no git, ou está em tests/ (ignorada por padrão)
Prova derrubou também o backendFaltam anotações de tipo (regras ANN do ruff); teste com uv run ruff check
