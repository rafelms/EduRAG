Proteção da main e fluxo por PR

Ruleset protege-main

CampoValorLembrete
Enforcement statusActiveO padrão é Disabled
Bypass listvaziaAdmin na lista ignora tudo
TargetInclude default branchA main
Restrict deletionsligada
Block force pushesligada
Require a pull request0 aprovaçõesO autor não aprova o próprio PR
Require status checksbackend, frontend, gitleaksSão os ids dos jobs no ci.yml e no security.yml; o modo estrito fica ligado

Caminho: Settings → Rules → Rulesets → New branch ruleset.

Fluxo de cada mudança

git switch main && git pull
git switch -c tipo/descricao       # ex.: ci/gitleaks
# ... edita, testa local ...
git add -p && git commit -m "ci: ..."
git push -u origin tipo/descricao
# abre o PR → espera backend + frontend verdes → Merge
git switch main && git pull
git branch -d tipo/descricao

Quando algo dá errado

SintomaCausa provável
Push direto na main ainda passaRuleset Disabled ou você está na bypass list
Check não aparece em "Add checks"O job não rodou recentemente: faça um push ou abra um PR antes
PR travado em "Expected — waiting"O workflow não disparou para esse PR (confira on.pull_request.branches) ou o nome do job mudou
Renomeei um job e o PR travouO check obrigatório tem o nome antigo: atualize o ruleset
"Branch is out of date"Modo estrito: clique em Update branch
