Identidade no dia a dia

aws configure set region us-east-1 --profile edurag
aws login --profile edurag                     # credencial de até 12 h
aws sts get-caller-identity --profile edurag   # Arn termina em :user/...
$env:AWS_PROFILE = "edurag"                    # para o Terraform, nesta sessão
aws logout --profile edurag
  • Root: MFA, sem access key, só para tarefa de root.
  • Usuário IAM: MFA, AdministratorAccess + SignInLocalDevelopmentAccess, sem access key.
  • Menor privilégio de verdade: nas identidades de máquina (instância, CI via OIDC).

State

  • Liga cada objeto real ao seu bloco no código. Local por padrão (terraform.tfstate); aqui, no S3.
  • É texto puro: valor de segredo em recurso vai parar nele. Segredo entra no Parameter Store por aws ssm put-parameter, à mão.
  • Backend S3: bucket, key, region, use_lockfile = true (a trava é um objeto <key>.tflock), encrypt. A trava pelo DynamoDB está obsoleta.
  • Bucket do state: versionamento ligado (recupera um state estragado), criptografia, bloqueio de acesso público.

Armadilhas

  • Identity Center no plano gratuito: a instância de organização cria uma AWS Organization. A conta vira paga e os créditos expiram na hora.
  • Plano gratuito e tipo de instância: só os elegíveis (t3.micro, t3.small, t4g.micro, t4g.small, c7i-flex.large, m7i-flex.large). Listar: aws ec2 describe-instance-types --filters Name=free-tier-eligible,Values=true --query "InstanceTypes[*].InstanceType" --output text.
  • Alerta não desliga nada: o Budget só manda e-mail. O teto da Anthropic, ao contrário, bloqueia.
  • credential_process no perfil default impede o aws login nesse perfil. Use um perfil com nome (edurag).
  • Terraform lendo o aws login: provider ≥ 6.23.0 e Terraform ≥ 1.15.0 (fonte não oficial). Erro típico: "No valid credential sources found".
  • Elastic IP cobra mesmo com a instância parada. O EduRAG não usa.
  • .tfstate, .terraform/ e *.tfvars fora do git: o .gitignore ainda não tem essas linhas (aula 0012).
