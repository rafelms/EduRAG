Identidade no dia a dia

aws configure set region us-east-2 --profile edurag
aws login --profile edurag                     # credencial de até 12 h; escolha o projeto
aws sts get-caller-identity --profile edurag   # Arn: assumed-role/AccountFullAccessRole/...
$env:AWS_PROFILE = "edurag"                    # para o Terraform, nesta sessão
aws logout --profile edurag
  • Builder ID: MFA; é ele que entra no console e no aws login.
  • Nenhuma access key na máquina nem no repositório.
  • Menor privilégio de verdade: nas identidades de máquina (a role da instância, na 0013).
  • Sem profile no código Terraform: a credencial vem do ambiente.

State

  • Liga cada objeto real ao seu bloco no código. Local por padrão (terraform.tfstate); aqui, no S3.
  • É texto puro: valor de segredo em recurso vai parar nele. Segredo entra no Parameter Store por aws ssm put-parameter, à mão.
  • Backend S3: bucket, key, region, use_lockfile = true (a trava é um objeto <key>.tflock), encrypt. A trava pelo DynamoDB está obsoleta.
  • Bucket do state: versionamento ligado (recupera um state estragado), criptografia, bloqueio de acesso público. Bucket novo já vem com bloqueio de acesso público, ACLs desligadas e SSE-S3; o versionamento vem desligado.
  • Nome: edurag-tfstate-<sufixo aleatório> (fica no repositório público; sem o ID da conta).
aws s3api create-bucket --bucket <nome> --region us-east-2 --create-bucket-configuration LocationConstraint=us-east-2
aws s3api put-bucket-versioning --bucket <nome> --versioning-configuration Status=Enabled
aws s3api get-public-access-block --bucket <nome>
aws s3api get-bucket-encryption --bucket <nome>
aws s3api list-object-versions --bucket <nome> --prefix <key>

Lock file e git

  • .terraform.lock.hcl vai para o git (é o uv.lock do Terraform). init -upgrade troca a versão.
  • Por padrão, só traz os hashes da sua plataforma. Para a CI: terraform providers lock -platform=windows_amd64 -platform=linux_amd64.
  • Fora do git: .terraform/, *.tfstate, *.tfstate.*, *.tfvars, crash.log e planos salvos.

Armadilhas

  • Conta "AWS (new)": sem root, sem usuário IAM com senha, região fixa e OIDC bloqueado. O caminho da aula 0011 original (root + usuário IAM) só vale para conta criada pelo "Sign up for AWS (advanced)".
  • Budget e créditos: o modelo "custo mensal" exclui Credit e Refund, então o alerta mede o uso antes do crédito.
  • create-bucket fora de us-east-1 sem LocationConstraint falha.
  • Identity Center no plano gratuito: a instância de organização cria uma AWS Organization. A conta vira paga e os créditos expiram na hora.
  • Plano gratuito e tipo de instância: só os elegíveis (t3.micro, t3.small, t4g.micro, t4g.small, c7i-flex.large, m7i-flex.large). Listar: aws ec2 describe-instance-types --filters Name=free-tier-eligible,Values=true --query "InstanceTypes[*].InstanceType" --output text.
  • Alerta não desliga nada: o Budget só manda e-mail. O teto da Anthropic, ao contrário, bloqueia.
  • credential_process no perfil default impede o aws login nesse perfil. Use um perfil com nome (edurag).
  • Terraform lendo o aws login: provider ≥ 6.23.0 e Terraform ≥ 1.15.0 (fonte não oficial). Erro típico: "No valid credential sources found".
  • Elastic IP cobra mesmo com a instância parada. O EduRAG não usa.
  • Security group sem saída: o Terraform remove a regra "allow all" padrão. Sem uma regra de saída 443, o agente do SSM não fica Online e o user_data não baixa nada.
  • t4g é ARM: as imagens do GHCR do EduRAG são só amd64.
  • T3 nasce unlimited: CPU acima da linha de base cobra à parte. Use cpu_credits = "standard".
  • .sh com CRLF: com core.autocrlf = true, o script chega ao Linux como /bin/bash\r. .gitattributes: *.sh text eol=lf.
  • Mudar o user_data sem user_data_replace_on_change só faz stop/start, e o script não roda de novo.
  • Trava do state: um apply esperando o yes já segura a trava. Se um comando morrer e a trava ficar, terraform force-unlock <id>, só com certeza de que ninguém mais está rodando.
