O ovo e a galinha

O Terraform guarda o state num bucket S3. Mas quem cria esse bucket? Se for o mesmo Terraform, ele precisaria do bucket para guardar o state do próprio bucket. Por isso o bucket do state é a última peça feita à mão da trilha, junto com o Budget. Ele fica fora do destroy e é o último a sair na etapa 15.

você (aws login)→terraform plan/apply→trava: <key>.tflock→state no S3→recursos na conta

Fonte: S3: Creating a general purpose bucket ("By default, all four Block Public Access settings are enabled", "By default, versioning is disabled for buckets", "All new objects uploaded to an S3 bucket are automatically encrypted with SSE-S3").

Por que versionar? Um apply que quebra no meio, ou um state sobrescrito por engano, deixa o Terraform sem saber o que existe na conta. Com versionamento, cada gravação do state vira uma versão nova, e a anterior continua recuperável. A documentação do backend chama isso de "highly recommended". (Terraform: Backend S3)

O nome precisa ser único em toda a AWS (na partição comercial), com 3 a 63 caracteres, só minúsculas, números e hífens. A documentação avisa para não pôr informação sensível nele, porque ele aparece nas URLs. (S3: bucket naming) O nome vai ficar no seu repositório público, dentro do bloco backend. Por isso, use edurag-tfstate- com um sufixo aleatório, e não o ID da conta.

Fora de us-east-1, o create-bucket exige --create-bucket-configuration LocationConstraint=us-east-2. Sem isso, o comando falha. (AWS CLI: create-bucket)

Fonte: Terraform: Backend S3. A trava pelo DynamoDB "is deprecated and will be removed in a future minor version": não use.

Onde não pôr a credencial: o backend e o provider aceitam profile = "edurag", mas não escreva isso no código. Na aula 0014, a CI roda init -backend=false sem perfil nenhum, e um nome de perfil fixo no código só existe na sua máquina. Use a variável da sessão: $env:AWS_PROFILE = "edurag". A documentação também recomenda manter as credenciais fora dos arquivos do backend, porque elas iriam parar na pasta .terraform e nos arquivos de plano. (Backend S3: partial configuration)

O lock file do provider: o uv.lock do Terraform

O terraform init grava o .terraform.lock.hcl com a versão escolhida de cada provider e os hashes dela. Depois disso, "Terraform will always re-select that version", até você pedir init -upgrade. A documentação manda versionar esse arquivo, para que uma troca de versão apareça num PR, como no uv.lock. (Terraform: Dependency lock file)

Armadilha para a 0014: por padrão, o lock só traz os hashes da plataforma onde você rodou o init (a sua é windows_amd64). A CI roda em linux_amd64. O comando terraform providers lock, com um -platform para cada plataforma, grava as duas de uma vez. (Dependency lock file)

O recurso de teste: grátis e com uma lição dentro

O primeiro ciclo usa um parâmetro do Parameter Store do tipo String, de valor inocente (por exemplo, "ola terraform"). Parâmetro padrão não cobra nada, nem na leitura. (Systems Manager pricing) Na 0014, a instância vai ler os segredos de lá.

Aposte: se em vez de String você usar SecureString com a chave do Claude como valor, ela fica protegida no state?

Resposta

Não. O SecureString é criptografado dentro do SSM, mas o Terraform guarda no state o valor que recebeu, em texto puro. (Terraform: sensitive data) É por isso que o valor dos segredos vai pelo aws ssm put-parameter, à mão, e o Terraform só dá permissão de leitura (registro 0011, aula 0011).

Mão na massa

Sem esqueleto. Cada bloco do HCL tem o link da documentação: leia o exemplo de lá e escreva o seu. Se travar, peça o esqueleto (sem valores), como na aula 0006.

  1. Sessão: num PowerShell novo, aws login --profile edurag (se a credencial de 12 h venceu) e $env:AWS_PROFILE = "edurag". Confira com aws sts get-caller-identity, agora sem --profile: se responder, a variável funcionou.
  2. Nome do bucket: gere um sufixo com -join ((48..57) + (97..122) | Get-Random -Count 6 | ForEach-Object { [char]$_ }) e monte edurag-tfstate-<sufixo>. Anote.
  3. Criar o bucket: aws s3api create-bucket com --bucket, --region us-east-2 e o --create-bucket-configuration da seção acima. A resposta traz um Location.
  4. Ligar o versionamento: aws s3api put-bucket-versioning com --versioning-configuration Status=Enabled. Confira com get-bucket-versioning: precisa responder "Status": "Enabled". (put-bucket-versioning)
  5. Conferir os padrões: aws s3api get-public-access-block (os quatro true) e aws s3api get-bucket-encryption (AES256, que é o SSE-S3).
  6. Branch: git checkout -b infra/base. Acrescente ao .gitignore as linhas da tabela "o que não entra no git".
  7. infra/versions.tf: um bloco terraform com required_version (aceitando a 1.17), required_providers com o hashicorp/aws fixado na 6.73.0 e o backend "s3" com os cinco argumentos da tabela. (terraform block · version constraints · backend S3)
  8. infra/providers.tf: o bloco provider "aws" com region = "us-east-2" e default_tags (por exemplo, Projeto = "edurag" e Gerenciado = "terraform"). Sem profile. (provider aws: default_tags)
  9. terraform init dentro de infra/. Procure na saída "Successfully configured the backend "s3"" e veja o .terraform.lock.hcl aparecer. Se der "No valid credential sources found", confira o passo 1 e me chame.
  10. infra/teste.tf: um aws_ssm_parameter do tipo String, com nome começando por /edurag/ e um valor inocente. (aws_ssm_parameter) Rode terraform fmt e terraform validate.
  11. terraform plan: leia antes de seguir. Quantos recursos ele vai criar? As tags do default_tags aparecem em qual atributo?
  12. Prova da trava: rode terraform apply e não responda o yes ainda. Em outro PowerShell (com $env:AWS_PROFILE definido e dentro de infra/), rode terraform plan. Ele precisa falhar com "Error acquiring the state lock". Enquanto isso, aws s3 ls s3://<bucket>/ --recursive mostra o arquivo .tflock. Volte ao primeiro terminal e responda yes.
  13. Conferir na conta: aws ssm get-parameter --name <nome> e terraform state list. No S3, o .tflock sumiu e o state ficou.
  14. terraform destroy: leia o plano de destruição e confirme. Depois, aws ssm get-parameter com o mesmo nome precisa dar ParameterNotFound.
  15. As versões do state: aws s3api list-object-versions --bucket <bucket> --prefix <key>. Quantas versões existem, e por quê?
  16. Fechar o PR: apague o teste.tf e rode terraform plan: ele precisa dizer "No changes". Rode terraform providers lock -platform=windows_amd64 -platform=linux_amd64 para a CI da 0014. O commit leva .gitignore, versions.tf, providers.tf e o .terraform.lock.hcl. Abra o PR infra/base.
